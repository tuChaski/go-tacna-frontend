# T058 · Visor geográfico público

Estado: implementación frontend en revisión. El cierre integral depende del
contrato de posición pública y de los pendientes de backend indicados abajo.
Rama: `feature/T058-visor-mapa`. PR hacia `develop`. Revisión: 27/11/2026.

## Comportamiento

`/mapa` abre Tacna sin cuenta y sin pedir la ubicación del visitante. Conserva
búsqueda, páginas de 8 rutas y 6 micros, enlaces `/mapa?ruta=4`, detalle de una
unidad y devolución del foco. Esos tamaños son paginación, no cuotas del plan.

El visor permite desplazar, acercar, alejar y **Ver todo el recorrido**. Dibuja
solo el `LineString` publicado. Valida tipo, orden longitud/latitud, rango,
valores finitos, mínimo de dos puntos distintos y máximo de 20 000 puntos.
Descarta el trazado completo si está corrupto, sin unir fragmentos inventados.
La ruta y sus unidades siguen consultables cuando no hay trazado compatible.

Solo se encuadra al cambiar de ruta o pulsar el botón de encuadre. Seleccionar
un micro o actualizar el listado no modifica la cámara manual. Las capas se
actualizan en una fuente y se retiran al abandonar el mapa. Cada instancia
elimina eventos, marcadores, controles, canvas y recursos al desmontar.
El montaje asíncrono se cancela también bajo React StrictMode.

El listado sigue disponible si fallan teselas, worker o gráficos. Se muestran
avisos y **Reintentar mapa**, sin reintentos propios ilimitados. Las animaciones
de cámara de los controles se desactivan y el CSS respeta reducción de movimiento.
El mapa no utiliza WebSocket, movimiento simulado, aforo ni ETA.

## MapLibre y carga

Se fija `maplibre-gl` **6.19.0**, compatible con las herramientas instaladas:
Node 24, React 19, TypeScript 6 y Vite 8. MapLibre no requiere un wrapper de React.
La biblioteca se importa dinámicamente al montar el visor; la landing no ejecuta
ese import. Leaflet y sus componentes administrativos se conservan.

La revisión en navegador detectó que la autodetección del worker de MapLibre 6
no funciona con los módulos renombrados de Vite. Se importa su worker con
`?worker&url`, se empaqueta en formato ES y se fija con `setWorkerUrl` antes
de crear el mapa. Worker, estilos de aplicación y código se sirven desde el
propio frontend; no se descargan scripts de un CDN.

El build advierte de chunks superiores a 500 kB: MapLibre pesa aproximadamente
1,10 MB minificado (302 kB gzip), su worker 551 kB y el módulo 3D previo 555 kB.
El mapa y su worker se solicitan al usar el visor. No se ocultan esas advertencias
subiendo el umbral de Vite.

## Proveedor y configuración

El estilo es local, definido en `proveedor-mapa.ts`, con raster **OpenStreetMap
Standard**: `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, teselas de 256 px,
zoom de fuente máximo 19. No usa claves ni un servicio de demostración de MapLibre.
Se observó la cobertura de Tacna en la revisión visual con calles reales.

La atribución `© OpenStreetMap contributors` permanece desplegada en el mapa,
con enlace a la licencia, y se incluye el enlace para informar errores del mapa.
El uso de los datos se rige por ODbL y el servicio de teselas tiene condiciones
adicionales. Consultadas las fuentes oficiales:

- [Política de teselas de OSM](https://operations.osmfoundation.org/policies/tiles/).
- [Licencia y atribución de OSM](https://www.openstreetmap.org/copyright).
- [Documentación de MapLibre y workers](https://maplibre.org/maplibre-gl-js/docs/).

OSM ofrece un servicio comunitario sin SLA; no representa capacidad reservada
para producción. Este uso interactivo no incluye descargas masivas, precarga
de ciudades, mapas sin conexión ni escaneo automático de teselas. El navegador
conserva su User-Agent y Referer y aplica la caché HTTP normal. No configurar
una política de Referer que suprima la identificación exigida por OSM.

Para sustituir el proveedor, revisar condiciones, cobertura, atribución y carga
previstas y modificar conjuntamente `estiloMapaPublico`, `ORIGEN_TESELAS` y la
validación `solicitudMapa`. La lista de fuentes es cerrada: admite únicamente
la plantilla HTTPS revisada, sin usuario, contraseña ni parámetros en la URL.
Las peticiones de mapa no pasan por Axios y usan credenciales `same-origin`:
como el origen de OSM es externo, no transmiten sus cookies ni tokens de la API.
Nunca introducir secretos en `VITE_*`, código o documentación.

Si infraestructura aplica CSP, debe permitir el worker ES del propio origen,
la conexión a `https://tile.openstreetmap.org` y los recursos de imagen necesarios
según la documentación de MapLibre. Coordinar esa configuración con infraestructura;
no se cambió el proxy ni la política de producción en esta tarea.

## Posición pública y privacidad

La API REST revisada todavía devuelve `conductor_actual.usuario` con DNI, correo
y teléfono; el detalle también incluye historial `posiciones`. El frontend los
descarta. **Ocultar datos en pantalla no corrige su exposición en la red.**
Alex confirmó que la corrección corresponde al equipo backend; no se modifica
backend, móvil ni la base de datos durante T058.

No hay un contrato REST confirmado para una posición pública mínima autorizada.
Por eso el adaptador real asigna `posicion: null` y muestra **Ubicación no
disponible**. No se reutilizan `posiciones`, `ultima_posicion` ni campos privados
como atajo. Que la API responda 200 no acredita autorización de esos campos.

El motor está preparado y probado con un modelo mínimo
`{ longitud, latitud, fecha }`, siempre que su publicación esté autorizada. Exige
coordenadas válidas y fecha ISO con zona; la fecha se presenta en hora de Perú.
Marcadores y tarjetas comparten selección. Esto se verifica con posiciones
ficticias en la escena de QA; no se afirma que los micros reales ya tengan GPS.
El validador no acredita permisos. Al acordarse el contrato, integrar únicamente
su campo permitido en el adaptador y repetir la verificación de red y selección.

Tampoco se afirma frescura de una posición: el umbral de señal de otros flujos
no se convierte automáticamente en política de vigencia del DTO REST.
El estado Disponible no implica circulación ni GPS reciente; la capacidad
máxima no representa ocupación. WebSocket corresponde a T060.

## Repetir las comprobaciones

Desde frontend, usando `npm.cmd` si PowerShell restringe `npm.ps1`:

```powershell
npm.cmd run lint
npm.cmd run build
npm.cmd run test:auth
npm.cmd run test:sesion
npm.cmd run test:rutas
npm.cmd run test:publico
npm.cmd run test:mapa
npm.cmd run test:mapa:tipos
npm.cmd run test:publico:api
npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

`test:publico:api` solo lee una API de loopback y no necesita credenciales.
No ejecutar las pruebas CRUD de escritura sobre los registros actuales.

Pantalla real: `http://127.0.0.1:5173/mapa`.
QA: `http://127.0.0.1:5173/pruebas/revision-visor.html`.

La página de QA permite variar el ancho y ejecutar comprobaciones del flujo,
errores de catálogo, marcadores y WebGL. Usa un adaptador HTTP ficticio dentro
de su propio iframe, un contexto de invitado aislado y una tesela lisa generada localmente. No consulta Laravel
ni descarga teselas de OSM. Las escenas se limitan a desarrollo en loopback y
no están en los entrypoints del build de producción. La consulta real nunca
importa ese adaptador ni lo utiliza para reemplazar una API caída.

Los escenarios manuales incluyen búsqueda `html`, `lenta`, `red`, `error500`
e `incompleta`; ruta 2 sin trazado/unidades, 3 retirada, 4 con detalle retirado,
5 con error de unidades y 6 con geometría incompatible. La segunda página
contiene un nombre largo. El escenario de marcadores es explícitamente ficticio.

## Evidencia y límites de la revisión

- Las pruebas automatizadas usan contratos y motor inyectado, sin GPU ni teselas reales.
- La integración pública contra Laravel es de solo lectura y se registra aparte.
- La revisión visual observa el navegador y los resultados de la escena de QA.
- No se realizaron sesiones con personas reales ni una auditoría con lector de pantalla.
- La regresión automatizada de autenticación, sesión y geometría administrativa
  no equivale a repetir un CRUD de escritura o login administrativo en navegador.

Los resultados finales y los comandos de Git se registran en [entrega-t058.md](entrega-t058.md).
Antes de publicación: corregir privacidad en backend, confirmar contrato de
posición pública y revisar que el proveedor seleccionado cubra la carga prevista.
